# 常见问题（汇报准备用）

| 问题 | 回答 |
|---|---|
| 四种任务类型是什么？ | 每类 100 题，共 400 题，都来自公开数据集。**yes/no**（BoolQ）：读一段文章，回答 yes 或 no。**classify**（AG News）：判断一篇新闻属于 World、Sports、Business、Sci/Tech 中的哪一类。**extract**（SQuAD）：从文章里摘出问题的答案，用 LLM 评审判断对错。**math**（GSM8K）：多步计算的文字题，看最终数字对不对。 |
| 为什么选这四类？ | 它们的难度和输出长度差别很大。yes/no 和分类只输出一两个词，抽取输出一小段，数学要写出推理过程、输出最长，本地跑也最慢、最费电。小模型在 yes/no 和抽取上接近云端，在分类和数学上差得多。 |
| task-rule 是什么？ | 只按题目类型分配：yes/no 和抽取走本地，分类和数学走云端，规则由 RQ1 的结果定。一半请求留在本地，碳排约为纯云端的一半，准确率是云端的 94%，而且是最快的策略。缺点是分到本地的题，不管小模型答没答对都用它的答案。 |
| cascade 是什么？ | 先让本地小模型答，再看它的置信度（输出每个词的平均对数概率）。高于阈值就用本地答案，低于阈值就把题再发给云端。阈值按任务设定，要求整体准确率比纯云端低不超过 0.02。被升级到云端的题要付两份时间和能耗，所以 cascade 比较慢。 |
| rule+cascade 是什么？ | 先按 task-rule 分配：分类和数学直接走云端；yes/no 和抽取先在本地答，没把握的再交给云端兜底。准确率能到云端的 98%，但约 73% 的请求最终走云端，碳排比 task-rule 高。 |
| oracle 是什么？ | 理论上限：假设事先知道本地会不会答对，只在本地答错时才走云端。现实中做不到。它能让约 75% 的请求留在本地，同时达到云端的准确率。cascade 和它之间的差距说明，置信度信号是瓶颈。 |
| fit-rule 是什么？ | task-rule 的按模型版本：对每个模型，挑出"放本地损失最小"的两类任务。Gemma 选了分类和抽取，准确率从 0.875 提到 0.890；Llama 和 Phi 选出来的就是原来的规则。 |
| 置信度 / AUROC 是什么？ | 置信度是模型输出每个词时的平均对数概率，越高说明模型越"有把握"。AUROC 衡量置信度能不能区分答对和答错：0.5 等于瞎猜，1.0 是完美区分。我们的结果只有 0.52–0.83，所以 cascade 常常判断错。 |
| 隐含碳是怎么算的？ | 隐含碳是制造设备时排放的碳，按寿命分摊到每次请求，分低/中/高三组假设，下面是中间值。**笔记本**：制造约 250 kg CO2e，用 4 年、每天 8 小时，约合每秒 6 毫克，乘以请求占用的秒数；本地和云端请求都要算，因为走云端时笔记本也在等。**云端服务器**：8 卡 GPU 服务器制造约 2500 kg，平均 6 kW、用 5 年、利用率 50%，约合每度电 19 克，乘以云端请求的耗电量（0.24 Wh）。 |
| 隐含碳的结果是什么？ | 纯本地碳排增加约 42%（本地运行本身耗电少，所以占比显得大），纯云端增加约 9%，策略排序不变。网络传输的碳排不到 1%。这些都是估算：Groq 的芯片没有公开碳足迹，用 GPU 服务器代替；训练时的碳排也没算进来。详见 `rq3/results/rq3_summary.md` 第 3 节。 |
| 逐小时碳强度有什么影响？ | 用 MISO 电网 2024 年的逐小时数据（平均 445 g/kWh，原来固定用 420）重新计算，用到云端的策略全年碳排变化不到 1%，GPU 上没有任何路由决定因此改变。 |
| 为什么不直接按碳排路由（carbon-aware）？ | 本地每次请求的碳排远低于云端，只看碳排会把所有请求都留在本地，准确率掉到 0.75。所以碳排只适合在质量达标以后，用来在几个选项之间做取舍。 |
